# 1.20.0 – Inventar-API und MCP für den Loxone-Abgleich

Ziel: Ein Assistent (z.B. Claude) kann die Homematic-IP-Konfiguration neben einem
Loxone-Config-MCP abfragen, beide abgleichen und gemeinsam darstellen – welche
HmIP-Kanäle in Loxone als Virtual UDP Input angelegt sind, welche fehlen und
welche Eingänge ins Leere zeigen.

Beide Endpunkte sind **rein lesend**: sie lesen nur den vorhandenen Snapshot,
senden keine HCU-Befehle und keine UDP-Pakete. Ausgegeben werden nur Felder aus
einer Allowlist (keine Tokens, MACs, Rohsnapshots oder beliebig verschachtelte Objekte).

## `GET /api/inventory`

`X-API-Key` erforderlich. Liefert:

- `rooms` – META-Gruppen (Räume) mit Geräte-IDs
- `devices` – ID, Label, Typ, Modell, Firmware, Raum; je Kanal Index, Typ, Label,
  aktuelle Werte und `loxone_variables` (exakt die Namen, die die Bridge sendet)
- `groups` – Nicht-Raum-Gruppen (Heizung, Schalten, Sicherheitszonen …) mit Mitgliedern,
  Werten und Loxone-Variablen
- `shelly` – Shelly-Cache (IP, ID, Name, Modell, Gen, Firmware, Anzahl Ausgänge)
- `counts`, `snapshot_ready`

## `GET /api/loxone/mapping`

`X-API-Key` erforderlich. Jede Variable, die beim Vollsync per UDP an den
Miniserver geht, mit Herkunft und Loxone-Befehlserkennung:

```json
{"variable": "hmip_3014F7…_ch1_on", "value": "1", "entity": "device",
 "id": "3014F7…", "label": "Licht Küche", "room": "Küche", "channel": "1",
 "field": "on", "channel_type": "SWITCH_CHANNEL", "kind": "bool",
 "command": "hmip_3014F7…_ch1_on@\\v"}
```

`kind` ist `bool`, `number` oder `text`. Textfelder (z.B. `windowState`) haben
`command: null`, da sie nicht als Analogwert in einen Virtual UDP Input passen.
Die Liste wird aus derselben Funktion erzeugt wie der UDP-Push und ist daher
immer deckungsgleich. Shelly-Energiewerte (`shelly_*`) stehen nicht im Snapshot
und erscheinen hier nicht.

## MCP-Server `ops/mcp_server.py`

Kleiner stdio-MCP-Server (nur Standardbibliothek) mit den Tools
`hmip_inventory` (optional `room`, `include_values`), `hmip_loxone_mapping`
(optional `filter`) und `hmip_diagnostics`. Er ruft ausschließlich die obigen
GET-Endpunkte und `/api/diagnostics` auf.

Beispiel für Claude Desktop / Claude Code (`mcpServers`):

```json
{
  "homematic-bridge": {
    "command": "python3",
    "args": ["/pfad/zu/homematic-bridge/ops/mcp_server.py"],
    "env": {
      "BRIDGE_URL": "http://<bridge-ip>:8080",
      "BRIDGE_API_KEY_FILE": "/pfad/zu/homematic-bridge/data/api_key.txt"
    }
  }
}
```

Alternativ `BRIDGE_API_KEY` direkt setzen. Zusammen mit dem Loxone-Config-MCP
kann der Assistent dann z.B. gefragt werden: „Welche HmIP-Fensterkontakte haben
noch keinen Virtual UDP Input in Loxone?“
